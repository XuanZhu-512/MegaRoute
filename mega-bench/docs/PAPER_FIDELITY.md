# MegaRoute 论文核心机制对齐

依据 AGENTS.md 的算法保真要求，核对仓库实际提供的论文
`MegaRoute_Universal_Automated_Large-Scale_PCB_Rout.pdf` 第 IV、V 节。
本仓库是研究复现；论文未公开的实现细节不能宣称与作者源码完全相同。

## 核心机制

| 论文 | 当前实现 |
|---|---|
| 式（2）、（3）：障碍感知步长及八方向扩展 | 近障碍 `delta=w`，远处 `delta=beta*w`；默认 `beta=5` |
| 式（4）、（5）：轴向、45° 对齐 | 相对固定终点生成；不随当前节点改用新的最近铜点 |
| 式（6）、（7）：换层、直接终点连接 | 保留换层候选及同层、距离小于步长且方向对齐的终点连接 |
| 第 IV-B 节：形状障碍与间距 | 不同网络且共享铜层才互为铜障碍；走线检查完整线宽，过孔检查全部贯穿层 |
| 式（8）：135° 约束距离 | `max(dx,dy)+(sqrt(2)-1)*min(dx,dy)`，用于搜索排序 |
| 第 IV-C 节：节点密度 | 固定 `d_min`，按几何位置与铜层检查；不按到达方向扩大状态空间 |
| 式（9）：DRC 权重 | 保留归一化 Logistic 公式；默认 `L=200,k=0.4,mu=10`，最多 20 轮 |

起点、终点、候选和代价均不含案例 ID 或特定板坐标分支。
到达方向仅用于检查路径转角，不参与节点身份和密度豁免。
精确同位置的较低代价路径可以更新既有状态；显式轴向、对角对齐和最终终点连接不会因密度检查被当作冗余探索丢弃。
这保留了必要的小幅坐标调整；普通障碍感知扩展仍按 d_min 过滤。具体工程边界见 [D3B_CURRENT_FAILURES.md](D3B_CURRENT_FAILURES.md)。
密度比较使用已有数值容差，防止浮点累加把恰好 1 mil 的相邻步长误判为小于 1 mil。

删除了此前偏离核心搜索的历史拥塞代价、停滞加密、小于 `w` 的扩展步长、
停滞提前结束、单连接 10 秒/5 秒预算、严格修复时间预留及额外严格搜索阶段。
旧配置中的 `history_weight`、`history_cell_mm`、`stagnation_rounds`、`refinement_levels`
已从模型和 schema 移除，显式报不支持，不会静默启用。

## 终端与 KiCad 适配边界

默认使用焊盘原有接入中心。只有该点不满足完整线宽的板框、开孔、禁布区或间距要求时，
才在该焊盘的实际铜区域内检查有限的边界/网格候选，选出每层一个固定合法接入点。
候选采样只发生在进入搜索之前，不产生多源候选云，也不改变搜索过程中终点的位置。
这样可以处理跨板边、中心处在板框开孔中的焊盘，同时保留论文的点到点搜索结构。
采样有限，不承诺找到所有连续空间可行接入点。

对于 MegaRoute，若中心/首选接入点搜索以 `search_exhausted` 耗尽前沿，增加一次接入点重试。
重试前在焊盘铜区域内生成有界候选（每轴最多 16 个采样间隔），按合法候选出口数、
到另一端的启发式距离及坐标确定性排序；按轮次选取另一个固定接入点，每层仍只有一个源和终点。
采样坐标不成为路由网格；每次搜索的步长仍为 `w`/`beta*w`，节点仍为 `(x,y,z)`，
密度、线宽、间距和 135° 约束不变。只有前沿耗尽会触发重试，超时、节点/记录预算不另行重置。
这是终端适配的工程补充，不是论文新增的探索操作，也不保证穷尽全部合法接入位置。

## 论文未具体描述的工程实现

- 多端网按最小生成树拆成两端需求，采用确定性需求顺序。
- 每轮拆除冲突/未完成需求及阻挡它们的新增铜，保留其余结果；权重严格按轮次计算。
  需要重布的集合内采用确定性轮换，避免始终按同一顺序重现冲突；routing_order=fixed 可用于对照。
- 输入固定铜和板框保持硬约束；可重布铜可在协商中临时冲突。
- 保存最佳合法结果；若轮次或资源耗尽时仍有违规，只输出合法子集，违规方案单独保留为诊断。
- 资源控制只保留整板时间、每次搜索节点数/记录数上限，不再给每对连接分配独立时间。
- 内部长度代价以 1 mil 为单位，文件中的几何坐标仍为 mm。

这些是明确列出的复现选择，不把论文没有说明的调度细节称作作者原实现。

## 结果清理与重测

按本次任务范围清理 D3-A、D3-B 下 MegaRoute 的已有结果：
D3-A 99 个标准目录及额外的 `terminal-regions-0034-20261118-132726` 目录，D3-B 10 个标准目录。
FreeRouting、KRT、TraceMaker 结果保留，D3-C 未清理。
原 MegaRoute 分数不再作为当前版本结果，汇总重建为待重测。

在仓库根目录执行以下命令；脚本自动编译，并重新导出、布线和用 KiCad 评估：

```bash
bash dataset/D3-A/run_batch.sh megaroute
bash dataset/D3-B/run_batch.sh megaroute
python mega-bench/tools/aggregate_results.py results/D3-A results/D3-B
```

脚本外层默认布线预算 600 秒、评分预算 120 秒；当前算法配置整板上限 300 秒，
节点上限每次搜索 100 万、记录上限 200 万。按实际完成的 `evaluation/metrics.json` 汇总，
未评估板不计为 0 分。需要继续改变参数时应记录独立配置，不能混用旧结果。
